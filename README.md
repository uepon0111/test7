# プロセカ リザルト画像読み取り

GitHub Pagesで動作する、Project SEKAIのリザルト画像向けOCR試作です。

## 構成

- `index.html` — UI
- `css/style.css` — UI
- `js/image.js` — グレースケール、二値化、画像切り出し
- `js/geometry.js` — 白枠・ジャケット・ゲージ・各欄の位置検出
- `js/ocr.js` — Tesseract.jsによるOCR
- `js/debug.js` — オーバーレイ・デバッグ表示
- `js/app.js` — 全体制御

## GitHub Pagesへの配置

ZIPを展開して、含まれているファイルをリポジトリの公開ディレクトリへそのまま配置してください。

`index.html` をGitHub Pagesの公開ルートに置く構成を想定しています。

## OCRについて

Tesseract.js 6.0.1をjsDelivr CDNから読み込みます。したがって初回のOCRにはインターネット接続が必要です。
日本語タイトルと英数字を同じOCRワーカーで処理し、領域ごとにOtsu / adaptive / 反転の候補を比較します。

## デバッグ

- 画像上に検出線を重ねて表示
- A〜Iの処理前・処理後画像
- 各領域の座標とOCR信頼度
- スキャン位置、検出座標、信頼度
- OCRの各候補の生テキストとconfidence

を表示します。

## 注意

この版は、提示されたリザルト画面のレイアウトを基準に「色・輝度の変化 + 周辺画素の中央値・平滑化・複数スキャン」を使って自動位置決定する構成です。
異なる端末比率、極端な圧縮、UI変更などでは検出がずれる可能性があります。その場合はデバッグ表示を見て、検出アルゴリズムの閾値を調整してください。


## 設計上のポイント

1. 白枠検出は中央付近の複数 x / 上部の複数 y をサンプリングし、単一画素では決めません。
2. ジャケットは1本のスキャンだけでなく、中央付近と下寄りの2本を使い、途中の絵柄による色切れを近接区間として結合します。
3. 難易度とレベルは隣接しているため、「背景に戻る場所」だけでは分離できません。連続したブロックを先に検出し、その内部の最大色差を境界として使います。
4. 判定欄は最初の2行の繰り返し間隔から行ピッチを推定し、GREAT/BADを含む5行へ外挿します。これにより文字そのもののノイズで1行だけ欠けても崩れにくくしています。
5. OCRは領域ごとに複数二値化候補を比較し、confidenceをデバッグへ出します。
